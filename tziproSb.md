Техническое задание: Система учёта экзаменов работников на базе Supabase

1. Общие сведения
    1.1. Назначение системы
        Разработка веб-приложения для отслеживания сроков сдачи экзаменов работников предприятия с целью своевременного направления их на обучение начальниками участков. Система полностью реализуется на базе платформы Supabase.
        
    1.2. Целевая аудитория

      Администраторы системы
      Помощники администраторов
      Начальники участков (пользователи)
      Косвенно - работники предприятия (не имеют доступа к системе)

    1.3. Объем данных

Текущее количество участков: 3 (с перспективой расширения до 50)
Количество профессий: 15
Текущее количество работников: ~200 (с перспективой расширения до 5000)
Предполагаемое количество пользователей: ~10-15

2. Роли и функционал
2.1. Администратор системы

Создание, редактирование и удаление участков
Создание, редактирование и удаление учетных записей пользователей
Создание шаблонов профессий с указанием необходимых экзаменов
Настройка периодичности сдачи экзаменов для каждой профессии
Просмотр данных по всем участкам и работникам
Подтверждение изменений дат экзаменов
Импорт данных работников из внешних источников (Excel)
Создание новостей
Ручное резервное копирование базы данных
Доступ ко всем функциям системы без ограничений

2.2. Помощник администратора

Просмотр данных по всем участкам и работникам
Подтверждение или отклонение изменений дат экзаменов
Участие в форуме
Мониторинг активности пользователей

2.3. Начальник участка (пользователь)

Просмотр данных только по своему участку
Добавление, редактирование и деактивация работников своего участка
Внесение изменений в даты сдачи экзаменов работников (с последующим подтверждением администратором)
Просмотр уведомлений и статистики по своему участку
Участие в форуме

3. Структура данных (таблицы в Supabase)
3.1. Участок (sections)

id (uuid, primary key)
name (text, unique)
created_at (timestamptz, default: now())
updated_at (timestamptz)
is_active (boolean, default: true)

3.2. Пользователь (users)

id (uuid, primary key)
full_name (text)
email (text, unique)
section_id (uuid, foreign key → sections.id)
role (text, enum: 'admin', 'admin_assistant', 'section_chief')
created_at (timestamptz, default: now())
last_action_at (timestamptz)
last_visit_at (timestamptz)
is_active (boolean, default: true)
activity_rating (integer, default: 0)

3.3. Шаблон профессии (profession_templates)

id (uuid, primary key)
name (text)
section_id (uuid, foreign key → sections.id)
created_at (timestamptz, default: now())
updated_at (timestamptz)
is_active (boolean, default: true)

3.4. Экзамен (exams)

id (uuid, primary key)
name (text, unique)
periodicity (integer) // в днях

3.5. Экзамены для профессии (profession_exams)

id (uuid, primary key)
profession_template_id (uuid, foreign key → profession_templates.id)
exam_id (uuid, foreign key → exams.id)
periodicity_override (integer, nullable) // переопределение периодичности для конкретной профессии

3.6. Работник (employees)

id (uuid, primary key)
full_name (text)
profession_template_id (uuid, foreign key → profession_templates.id)
section_id (uuid, foreign key → sections.id)
is_active (boolean, default: true)
created_at (timestamptz, default: now())
updated_at (timestamptz)

3.7. Экзамены работников (employee_exams)

id (uuid, primary key)
employee_id (uuid, foreign key → employees.id)
exam_id (uuid, foreign key → exams.id)
exam_date (date)
next_exam_date (date, вычисляемое поле)
updated_by (uuid, foreign key → users.id)
updated_at (timestamptz)
pending_date (date, nullable) // предлагаемая новая дата
pending_until (timestamptz, nullable) // время до автоматического отклонения

3.8. Новость (news)

id (uuid, primary key)
title (text)
content (text)
published_at (timestamptz, default: now())
author_id (uuid, foreign key → users.id)

3.9. Резервное копирование (backups)

id (uuid, primary key)
created_at (timestamptz, default: now())
file_size (integer)
file_path (text)
created_by (uuid, foreign key → users.id)

3.10. Форум (forum_topics)

id (uuid, primary key)
title (text)
content (text)
author_id (uuid, foreign key → users.id)
created_at (timestamptz, default: now())
updated_at (timestamptz)

3.11. Сообщения форума (forum_messages)

id (uuid, primary key)
topic_id (uuid, foreign key → forum_topics.id)
content (text)
author_id (uuid, foreign key → users.id)
created_at (timestamptz, default: now())
updated_at (timestamptz)

Обеспечить возможность ИИ начинать проект с нуля или продолжать с текущего состояния, автоматически определяя необходимость запроса отчета о прогрессе, с обязательной проверкой завершения этапов.

ИИ анализирует входной запрос и ТЗ для определения состояния проекта.
Если отчет или артефакты не предоставлены, ИИ начинает с первого этапа.
Если отчет или артефакты предоставлены, ИИ анализирует их и продолжает с соответствующего места.
Если данных недостаточно, ИИ запрашивает отчет о прогрессе.

A. Приложения
A.1. Глоссарий

Участок — структурная единица предприятия
Профессия — должность работника с определенным набором требуемых экзаменов
Экзамен — проверка знаний работника, имеющая срок действия
Шаблон — набор параметров профессии, включающий требуемые экзамены и их периодичность
Supabase — платформа для разработки с открытым исходным кодом, предоставляющая PostgreSQL базу данных, аутентификацию, API и хранилище
RLS — Row Level Security, механизм PostgreSQL для контроля доступа к строкам таблиц
JWT — JSON Web Token, способ безопасной передачи информации о пользователе
