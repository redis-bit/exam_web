# Руководство по управлению резервными копиями

## Обзор функциональности

Система резервного копирования позволяет администраторам создавать полные резервные копии всех данных системы и восстанавливать их при необходимости.

## Доступ к функциональности

- **Доступ**: Только для пользователей с ролью `admin`
- **Расположение**: Dashboard → "💾 Резервные копии"

## Основные возможности

### 1. Создание резервной копии

**Что включается в резервную копию:**
- Участки (sections)
- Пользователи (users)
- Работники (employees)
- Экзамены работников (employee_exams)
- Экзамены (exams)
- Шаблоны профессий (profession_templates)
- Связи профессий и экзаменов (profession_exams)
- Новости (news)

**Процесс создания:**
1. Нажмите кнопку "Создать резервную копию"
2. Подтвердите действие в диалоговом окне
3. Система автоматически:
   - Экспортирует данные из всех таблиц
   - Создает JSON файл с временной меткой
   - Сохраняет файл в Supabase Storage
   - Записывает информацию о копии в таблицу `backups`

**Формат файла:**
```json
{
  "created_at": "2024-01-15T10:30:00.000Z",
  "created_by": "user-uuid",
  "creator_name": "Имя администратора",
  "version": "1.0",
  "tables": ["sections", "users", "employees", ...],
  "data": {
    "sections": [...],
    "users": [...],
    "employees": [...],
    ...
  }
}
```

### 2. Скачивание резервной копии

**Процесс:**
1. В списке резервных копий найдите нужную
2. Нажмите кнопку "Скачать"
3. Файл будет загружен в папку Downloads

**Информация о копии:**
- Дата и время создания
- Размер файла
- Имя создателя

### 3. Восстановление из резервной копии

**⚠️ ВНИМАНИЕ: Восстановление удаляет все текущие данные!**

**Процесс:**
1. В разделе "Восстановление из файла" выберите JSON файл резервной копии
2. Нажмите "Восстановить из файла"
3. Подтвердите действие (будет предупреждение о замене данных)
4. Система автоматически:
   - Проверяет формат файла
   - Очищает существующие таблицы (кроме `users`)
   - Восстанавливает данные в правильном порядке с учетом зависимостей

**Порядок восстановления таблиц:**
1. sections (участки)
2. users (пользователи) - используется upsert для сохранения новых пользователей
3. exams (экзамены)
4. profession_templates (шаблоны профессий)
5. profession_exams (связи профессий и экзаменов)
6. employees (работники)
7. employee_exams (экзамены работников)
8. news (новости)

### 4. Удаление резервной копии

**Процесс:**
1. В списке резервных копий найдите ненужную
2. Нажмите кнопку "Удалить"
3. Подтвердите действие
4. Система удалит:
   - Файл из Supabase Storage
   - Запись из таблицы `backups`

## Рекомендации по использованию

### Регулярность создания копий
- **Ежедневно**: При активном использовании системы
- **Еженедельно**: При умеренном использовании
- **Перед важными операциями**: Импорт данных, обновления системы

### Хранение копий
- Скачивайте важные копии на локальный компьютер
- Храните копии в нескольких местах
- Регулярно проверяйте возможность восстановления

### Безопасность
- Файлы резервных копий содержат все данные системы
- Храните их в безопасном месте
- Не передавайте файлы третьим лицам

## Устранение неполадок

### Ошибка "Недостаточно прав"
- Убедитесь, что вы вошли как администратор
- Проверьте роль пользователя в таблице `users`

### Ошибка создания копии
- Проверьте подключение к интернету
- Убедитесь, что Supabase Storage настроен
- Проверьте права доступа к таблицам

### Ошибка восстановления
- Проверьте формат JSON файла
- Убедитесь, что файл не поврежден
- Проверьте совместимость версий

### Большой размер файла
- Резервные копии могут быть большими при большом количестве данных
- Рассмотрите возможность архивации старых данных
- Используйте сжатие при хранении файлов

## Техническая информация

### Требования к системе
- Supabase Storage должен быть настроен
- Bucket "backups" должен существовать
- RLS политики должны разрешать доступ администраторам

### Формат данных
- JSON с UTF-8 кодировкой
- Структурированные данные с метаинформацией
- Сохранение UUID и связей между таблицами

### Ограничения
- Максимальный размер файла ограничен Supabase Storage
- Время создания копии зависит от объема данных
- Восстановление заменяет все данные (кроме новых пользователей)
