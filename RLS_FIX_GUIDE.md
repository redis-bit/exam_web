# Исправление RLS проблемы с employee_exams

## 🚨 Проблема:
Ошибка `new row violates row-level security policy for table "employee_exams"` возникает, когда пользователь участка создает работника. Триггер пытается автоматически создать экзамены, но RLS политика блокирует это.

## 🔍 Причина:
1. **Триггер выполняется в контексте пользователя** (не системы)
2. **RLS политика** не разрешает создание экзаменов через триггер
3. **Отсутствует исключение** для системных операций

## ⚡ Решение в 2 этапа:

### Этап 1: Исправьте RLS политики
Выполните в Supabase Dashboard → SQL Editor:
```sql
-- Содержимое файла database/fix_rls_employee_exams.sql
```

**Что исправляет:**
- ✅ Пересоздает политики для `employee_exams`
- ✅ Добавляет исключение `auth.uid() IS NULL` для триггеров
- ✅ Разрешает начальникам участков создавать экзамены для своих работников

### Этап 2: Исправьте триггеры
Выполните в Supabase Dashboard → SQL Editor:
```sql
-- Содержимое файла database/fix_trigger_security.sql
```

**Что исправляет:**
- ✅ Добавляет `SECURITY DEFINER` к функциям триггеров
- ✅ Устанавливает `search_path = public`
- ✅ Пересоздает триггеры с правильными правами

## 🔧 Ключевые изменения:

### В RLS политике INSERT:
```sql
-- ДОБАВЛЕНО: Исключение для триггеров
OR auth.uid() IS NULL
```

### В функциях триггеров:
```sql
-- ДОБАВЛЕНО: Права владельца функции
SECURITY DEFINER
SET search_path = public
```

## 📊 Логика RLS политик:

### **SELECT** - Кто может видеть экзамены:
- ✅ Админы и помощники - все экзамены
- ✅ Начальники участков - экзамены работников своего участка

### **INSERT** - Кто может создавать экзамены:
- ✅ Админы и помощники - любые экзамены
- ✅ Начальники участков - для работников своего участка
- ✅ **Триггеры** - системные операции (`auth.uid() IS NULL`)

### **UPDATE** - Кто может изменять экзамены:
- ✅ Админы и помощники - любые экзамены
- ✅ Начальники участков - экзамены работников своего участка

### **DELETE** - Кто может удалять экзамены:
- ✅ Только админы и помощники
